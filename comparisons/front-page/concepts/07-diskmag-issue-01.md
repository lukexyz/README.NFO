# 07 · DISKMAG ISSUE #01: the coverdisk edition

**One-liner.** The README is issue 01 of a disk magazine. An animated
contents-screen cover sits on top. The first article is the coverdisk, which
gets you running in three steps. Then come reviews and screenshot pages full of
real headers, a "same style, three projects" test, a Claude Code vs Codex
shootout, the charts, an install tutorial, a letters page and an `[ EOF ]`. In
light mode the section kickers look like a printed magazine; in dark mode they
look like a diskmag reader.

Angle 07 from the ten. It differs from the others like this:

- It is not a release NFO (01), a boot intro (02), an installer (03), a
  fighter select (04), a BBS menu (05), an attract loop (06), an options screen
  (08), a terminal reel (09) or a CD launcher (10).
- Its organising idea is editorial: a magazine with articles. That gives it a
  natural place for many examples (reviews, screenshot pages, charts) and for
  the explanations (tutorial, shootout, letters) without the page reading like
  documentation.

All numbers below were recomputed from the repo on 2026-11-11 (refresh of
the 2026-10-13 draft, with the new engine trial and build-log figures).
The build script recomputes them, so none are typed into the README by hand.

---

## 1. The idea in 30 seconds

- **The cover is the contents page.** The hero is a diskmag reader screen.
  The README.NFO masthead and an `ISSUE 01` box sit above a seven-item menu. An
  inverse-video selection bar steps through the menu, and a preview window shows
  each article's art. One scroller runs along the bottom.
- **Article 01 is the coverdisk.** Gaming magazines taped a disk to the cover.
  Here the disk is the tool: three numbered steps, one command, the engine
  choice and a private-repo tip, all in the first screen and a half.
- **The middle of the mag is the examples.** It has six floated reviews (text
  wraps round the art, like a printed page) and a 20-tile screenshot wall. A
  matrix shows the same five styles drawn for three different projects. An
  ASCII corner and an optional back-cover contact sheet of every header finish
  it.
- **The back of the mag is the rest of the journey.** The shootout explains
  Claude Code vs Codex honestly. The charts graph the catalogue from the data.
  "From gallery to README" shows the one-number install. Letters is the FAQ, in
  `<details>`. News lists what shipped, and Credits ends in `[ EOF ]`.
- **Issue numbers keep it truthful.** Issue 01 launches with the new pipeline
  (`npx readme-nfo`, Claude or Codex, local folder). Until then the same layout
  ships as **Issue 00 · preview**, with today's true command and a note on what
  is coming (section 4).
- **Print in light, disk in dark.** Each article opens with a thin kicker strip
  in a `<picture>` pair. In light mode it is cream paper, black ink, a red
  number block and halftone dots, so the white GitHub page reads as a printed
  magazine. In dark mode it is a black reader bar with pixel type and a copper
  rule. GitHub's two themes become two editions of the same magazine.

### 2.4 Article 04: Shootout, Claude Code vs Codex

Kicker: `04 SHOOTOUT`. This is a magazine head-to-head, not a select screen.
The spec sheet is a 35-column text block, which reads on a phone where a
Markdown table would scroll sideways.

````markdown
## Shootout: Claude Code vs Codex

Same brief, same checker, same gallery. The engine only changes who
draws.
````

```text
          CLAUDE CODE  CODEX
 choose   --claude     --codex
 sign in  run claude   codex login
 runs as  claude -p    codex exec
 tools    none         read-only
 billed   Claude plan  ChatGPT plan
          or API key   or API key
 1 header 1:14 Sonnet  2:31 default
```

````markdown
<sub>Trial: one header each on 2026-11-11, same brief and same schema.
Claude Code ran Sonnet; Codex ran the account's default model. Both
passed the checker. A first look, not a benchmark;
tools/front-page/bench.json holds the measured runs.</sub>

**Verdict:** both draw valid headers. Use the one you already pay for.

**About these galleries.** Most headers in this issue were drawn by
Claude Opus in long multi-pass sessions (median 41 minutes of drawing
and critique a header, across the 158 runs logged in
examples/build-log.csv). A CLI batch draws each header in one pass,
so make a few batches and keep the best.
````

- The last paragraph sets honest expectations. It comes from the research
  finding that the showcase came from long Opus runs, not the public CLI.
- Trial facts (2026-11-11): Claude Code `claude -p --json-schema --tools ""`
  on Sonnet exited 0 in 74 s; its SVG passed `validateResponse` and rendered
  cleanly at 830 and 375 px. Codex `exec --output-schema` exited 0 in 151 s
  on the account's configured model (27,523 tokens); valid, but its subtitle
  touched the wordmark and small text was illegible at 375 px. The page never
  claims one engine "wins": the models and settings differed.
- The median is the `total_min` column of the committed rows (158 at
  `HEAD`; the working copy has 168 including uncommitted MediaLog rows).
  Wall-clock `elapsed_min` is longer (median 73), because runs overlapped.
- The "1 header" row and the median are read from `bench.json` and
  `build-log.csv` (committed rows) at build time.

## 3. The hero: `docs/front/cover-01.svg`

A diskmag reader's contents screen, at 960x540 (16:9). It is an opaque
panel with a 10 px rounded bezel drawn inside the SVG, so it reads on white and
on `#0d1117`. It follows the canon's intro rule: one logo, one effect, one line
of moving text.

```text
┌──────────────────────────────────────────────────────────────────────┐
│  README.NFO   (chrome pixel logo, 5x7 glyphs at x10)   ┌───────────┐ │
│                                                        │ DISKMAG   │ │
│                                                        │ ISSUE 01  │ │
│                                                        │ NOV 2026  │ │
│                                                        └───────────┘ │

│  IN THIS ISSUE                    ┌─ PREVIEW ──────────────────────┐ │
│ ►01 COVERDISK          RUN IT     │                                │ │
│  02 REVIEWS       260 HEADERS     │  art for the selected article: │ │
│  03 SAME STYLE     3 PROJECTS     │  7 slots, 2.5 s each, with a   │ │
│  04 SHOOTOUT  CLAUDE VS CODEX     │  0.2 s crossfade               │ │
│  05 CHARTS         153 STYLES     │                                │ │
│  06 INSTALL        ONE NUMBER     │                                │ │
│  07 LETTERS           Q AND A     └────────────────────────────────┘ │
│ ░▒▓ README.NFO ISSUE 01 ► RETRO README HEADERS DRAWN FRESH FOR ..▓▒░ │
│                                               SCROLL DOWN TO READ ▼  │
└──────────────────────────────────────────────────────────────────────┘
```

**Parts:**

- **Masthead:** `README.NFO` in 5x7 pixel glyphs at scale 10 (70 px tall). The
  fill is a chrome gradient split at a horizon line: white to periwinkle to
  deep blue above, warm orange to cream below. The `ISSUE 01 / NOV 2026` box
  is in amber and white. The issue number and date come from `issue.json`.
- **Contents menu:** seven rows at scale 4 (28 px; about 10 px on a phone).
  The short right-hand labels are at scale 2 and purely decorative on phones.
  Their numbers (260, 153) are generated.
- **The one effect:** an inverse-video selection bar. A 496x34 rect with
  `mix-blend-mode: difference` steps down one row every 2.5 s (a 17.5 s loop
  over 7 rows), turning the selected row dark on amber, like a real diskmag
  menu. A `►` cursor rides with it.
- **The preview window:** 360x280 px. One original flat-pixel vignette per
  article fades in for its slot:
  1. A 3.5-inch disk with a README.NFO label.
  2. Six tiny abstract "screens" in different palettes.
  3. Three identical test cards with different accent colours.
  4. Two name plates, CLAUDE CODE and CODEX, either side of a VS, each with a
     progress bar.
  5. Thirteen bars whose heights are the real family counts, from
     `styles.json`.
  6. A mini README page with a coloured header block at the top.
  7. An envelope with Q and A lines.

  No logos and no real artwork are reproduced.
- **The one moving line:** a scroller at scale 3 runs right to left on a 40 s
  seamless loop: `README.NFO ISSUE 01 ► RETRO README HEADERS DRAWN FRESH FOR
  YOUR PROJECT ► 153 STYLES IN 13 FAMILIES ► 260 EXAMPLE HEADERS ► CLAUDE
  CODE OR CODEX ► PRIVATE REPOS WELCOME ► MIT ►`. Numbers are generated.

**Animation rules:**

- Only CSS keyframes, never SMIL, so `@media (prefers-reduced-motion:
  reduce)` can stop everything.
- Nothing flashes. The bar moves once every 2.5 s.

**Reduced-motion still, and the t=0 frame:** these are the same composed
frame. The bar sits on 01 COVERDISK, the preview shows the disk, and the
scroller is parked with `README.NFO ISSUE 01 ► 153 STYLES` visible.

**Build:**

- Glyphs are defined once in `<defs>` as unit paths and placed with `<use>`,
  with no `<text>` and no fonts.
- The estimate is about 45-60 KB, against a 100 KB budget.
- The 5x7 glyph table comes from `examples/readme-nfo/src/lib.mjs`, moved to
  a shared `tools/lib/pixel-font.mjs` with `►`, `▼` and `·` added. That file's
  hard-coded `styles: 152` is the source of the stale count, so the cover takes
  its numbers from `loadCatalogue()` instead.

**Social card:**

- `docs/front/social-01.png` (1280x640) is a static relayout of the same
  parts: masthead, issue box, menu, and the coverline "RETRO HEADERS FOR YOUR
  README".
- It is rendered by Playwright from `social-01.svg`.
- The owner uploads it in the repo settings.

## 6. New assets and scripts

All are generated by deterministic Node scripts and rebuilt with `npm run
front-page`. CI runs `npm run front-page -- --check` and fails if the
committed README or assets differ from a fresh build.

| File | Made by | Notes |
| --- | --- | --- |
| `docs/front/cover-01.svg` | `tools/front-page/cover.mjs` | The hero. ~45-60 KB, CSS keyframes, reduced-motion still. |
| `docs/front/kicker-0{1..7}-{light,dark}.svg` (14 files) | `tools/front-page/kickers.mjs` | Static. 960x64 (01 is 960x140 with the coverdisk). Light: cream paper, black ink, red number block, halftone. Dark: black reader bar, amber pixel kicker, copper rule. ~3-6 KB each. |

| `tools/front-page/issue.json` | hand-edited data | Issue number and date, mode 0/1, review picks and copy, wall rows, chart order, family labels, letters, credits. |
| `tools/front-page/counts.mjs` | — | `git ls-files` header and gallery counts; `loadCatalogue()` styles and families; SVG/text capability; animated and reduced-motion counts; committed build-log median. |
| `tools/front-page/transcript.mjs` | — | Runs the real CLI with the fake agent and captures the terminal block. |
| `tools/front-page/bench.json` (+ `tools/bench-engines.mjs`) | measured | Per-engine times for the shootout, dated. |
| `tools/front-page/README.template.md` + `build.mjs` | — | Renders `README.md`, then lints it (below). |
| `tools/lib/pixel-font.mjs` | extracted | Shared 5x7 glyphs with `►`, `▼` and `·` added. |

`build.mjs` lints the result. It fails when:

- a linked or pictured file is missing or untracked;
- a heading anchor does not resolve;
- an `img` has no `alt` (decorative kickers use `alt=""` deliberately);
- a code block is wider than 80 columns, or a must-read block (the command,
  coverdisk panel, spec sheet, charts, options or credits) wider than 36;
- a code block uses a grid-breaking glyph (`◆◇✓✔★☆▶◀`);
- a catalogue style or family name appears on the page;
- a banned scene-piracy term appears as a whole word (crack, cracked,
  cracktro, keygen, warez, serial, supplied by, nuke). The page itself uses
  none of them; it says "demo intros" instead.

After the lint it runs `tools/preview.mjs README.md` for desktop, mobile, light
and dark screenshots.

## 7. The journey (visitor to installed header)

1. **Land.** The cover animates through the contents. The pitch says what it
   is, and the contents line jumps anywhere. Within one screen there are three
   steps and one command.
2. **Choose an engine.** Step 1 names both agents. The tool auto-detects
   whichever is signed in, asks once if both are, and takes `--claude` or
   `--codex`. The shootout explains the difference and the letters answer
   "both".
3. **Run.** `npx readme-nfo` in the project folder. The terminal shows
   `AGENT Claude Code (switch: --codex)`. Private, GitLab or unpushed projects
   need nothing, because facts come from disk. The tip box says so before the
   visitor can worry.
4. **Wait, with something to look at.** The NFO-styled gallery opens at once
   and fills three headers at a time. Each card shows its number and a
   copyable `npx readme-nfo use N`.
5. **Choose.** The terminal asks `Install which header? [1-10, Enter =
   later]`. Pressing Enter keeps the batch for later.
6. **Install.** The SVG and MIT notice go to `.github/readme-nfo/`, and a
   marked block goes at the top of the README. The alt text is neutral, with
   no style names.
7. **Review and commit.** The tool never commits. Article 06 shows the exact
   block, so `git diff` holds no surprises.
8. **Come back.** `npx readme-nfo use 4` swaps the header. A new run draws
   styles not used before. The letters cover editing (the batch's `src/`
   scripts) and `--resume`.

In Issue 00 the journey is the honest current one: a GitHub URL, Codex only,
`GH_TOKEN` for private repos, and manual copying. The page says so.

## 9. Mobile and dark mode

**Phones (about 309-364 px column):**

- **Hero.** It scales to about 0.35x. The masthead is about 25 px tall and
  the menu rows about 10 px, so it is legible. The scroller is texture.
- **Instructions.** Plain Markdown steps that wrap. The only command block is
  14 columns.
- **Text blocks.** Every must-read block is 36 columns or fewer: coverdisk
  panel, shootout, catalogue chart, numbers, options and credits. A 375-390 px
  phone shows about 34-36 columns in SF Mono and about 40 in Consolas, so they
  show in full with no sideways scroll. Only the install transcript (real CLI
  output; its prompt line is 46) and the reference HTML block scroll.
- **Reviews.** Each float becomes full width with its text directly below, so
  captions stay attached.
- **Walls.** 150 px tiles go 2-up on every phone (304 px). The same-style rows
  each start with a `<sub>` project label, so they still make sense as 2+2+1.
- **Letters.** Closed `<details>`, one tap each.

**Light mode, the printed edition:**

- The kickers are cream paper with black ink, a red number block and
  halftone. The white page reads as a magazine with screenshots printed on it,
  so dark tiles look like photos, not slabs.
- The hero is an opaque bezelled monitor panel.
- Text blocks sit on `#f6f8fa` as dark-on-grey listings.

**Dark mode, the disk edition:**

- The kickers are black reader bars with amber pixel kickers and copper rules.
  They melt into `#0d1117`, so the page reads like a diskmag on screen.
- The hero bezel is nearly invisible against the page.

**Reduced motion:** the hero shows its composed still. Every example tile has
its own still: all 264 committed animated SVGs carry a
`prefers-reduced-motion` rule.

## 10. Why it is cool

- **It turns the README into a thing people browse and bookmark.** A magazine
  invites scrolling: reviews, screenshots, charts and letters. It carries
  41-plus real headers without becoming a spreadsheet like today's 16-row
  table.
- **The diegetic parts are the functional parts.** The contents screen is the
  table of contents, and the coverdisk is the install. The shootout is the
  engine choice, the letters are the FAQ, the charts are the catalogue, and
  the credits end in `[ EOF ]`.
- **"Same style, three projects" proves the core promise** better than any
  claim: the art is made for your project.
- **Two editions, free.** Light mode becomes print and dark mode becomes disk.
  That fixes the black-slab-on-white problem by leaning into it.
- **Honesty is built in.** Issue numbers separate what ships now from what
  ships next. The shootout states its caveats, and every number is computed.
- **Very 90s gaming:** coverdisks, review pages, charts and a letters page.
  NFO grammar (dot leaders, ▄▀ frames, `─[ ]─` rules, `[ EOF ]`) holds the text
  blocks together.

## 11. Weaknesses

- **Long.** About 6,500 px on desktop and roughly 10,000 px on phones,
  although the instructions are in the first screen and a half. Mitigation:
  fold the wall's row D and the back cover.
- **Less "NFO" than a pure text concept.** The magazine frame is the star,
  with NFO grammar in the details. Visitors who want a wall of ASCII get it
  only in the text blocks and the ASCII corner.
- **The float layout is the riskiest GitHub trick in the concept** and must be
  proven on a scratch repo first.
- **Castaway leads the wall:** 16 of the 41 images, and 13 of the 20 wall
  tiles. The page shows six projects, but the CASTAWAY wordmark still repeats.
  That improves when MediaLog is committed and the README.NFO set is
  regenerated.
- **More assets to maintain:** a hero, 14 kickers, a social card and an
  optional poster. All are scripted, but there are more moving parts than in a
  one-image concept.
- **Diskmags are niche.** The magazine-and-coverdisk idea is widely
  understood, but the specific diskmag reader look is a deep cut.
