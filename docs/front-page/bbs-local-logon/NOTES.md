# 05 BBS LOCAL LOGON: build notes

## The concept

The front page is a 90s ANSI bulletin board that you have just dialled into.

- **Hero.** The logon screen: a blue status bar, a pixel README.NFO logo, a main menu and a last-callers list.
- **Hotkeys.** `[D] [I] [F] [S] [H] [G]` are the table of contents. Each one links to a real heading anchor.
- **The door.** The generator is a *door*: a small program that runs on your machine. "Local logon" turns the private-repo answer into part of the story: the door reads your folder, so it needs no token.
- **File areas.** The 13 catalogue families are 13 numbered file areas.
- **The core flow.** It is shown as a BBS file listing: BATCH 1 holds #01-#10, a "make 10 more" divider follows, then BATCH 2 holds #11-#20 on the same gallery.

Section order follows `build/brief-05.md`:

1. Hero, then H1, pitch, proof line and hotkeys.
2. **[D]oor:** a one-line intro, the bare `npx readme-nfo`, the canonical 3 steps word for word, three engine/private keys, the canonical engine and private-repo text, a door-screen block, the canonical "Want more?" text, the BATCH 1 / BATCH 2 listing, and the agent-route TIP.
3. **[I]nstall:** "number 3", `use 14`, the canonical "what changes" and undo text, and the marked block in a `<details>`.
4. **[F]iles:** 6 live picks, "Same door, three callers", then 13 file-area rows. Each row has 5 tiles (4 for print and xfer), neutral captions, and a `<details>` list of the area's headers.
5. **[S]etup:** an option table, plus every other option and URL mode in a `<details>`.
6. **[H]elp:** one sign-in TIP with install links for both agents, then how long it takes, what leaves your machine, why the examples look polished, and how to report a problem.
7. **[G]oodbye:** the credits block, closing with `+++ATH0` / `NO CARRIER` / `[ EOF ]`, then links.

## Known limits

- **Hero in full-page shots.** In `shoot.mjs` full-page shots the hero looks almost black. Chromium pauses an off-screen `<img>` SVG and draws its paused frame. The hero sits below GitHub's file list, about 956 px down on desktop. On a real visit it paints as soon as it scrolls into view: see `shots/hero-in-view-*.png`, taken 3 s off-screen and then 1.5 s or 5 s in view. The `*-reduced-t500.png` shots show the finished page.
- **Hero on phones.** At 309 px, the hero's menu labels, stats line, last callers and footer read, but the menu descriptions are small. Everything in them is repeated in the text below.
- **Code blocks.** The marked `<details>` html block is 36 columns, so it scrolls sideways on a phone. A path cannot be split, and every other block is 30 columns or fewer.
- **Picks on phones.** Pick captions sit under each pair, so on phones they follow both images.
- **Weight.** About 1.7 MB in total: hero 29 KB, keys about 15 KB, 63 tiles 0.9 MB, and 6 live picks plus 3 off-air headers about 0.8 MB.

## Rebuild

From the repository root (each script finds the repository from its own path):

```sh
B=docs/front-page/bbs-local-logon
node $B/src/hero-bbs.mjs $B/assets/hero-bbs.svg
node $B/src/keys.mjs $B/assets/keys
node $B/src/thumbs.mjs $B/src/curation.json $B/assets/thumbs   # Playwright, about 1 min
node $B/src/social.mjs $B/assets/hero-bbs.svg $B/assets/social.png
node $B/src/build.mjs            # writes README.md; --check exits 1 if stale
node tools/front-page/render.mjs $B
node tools/front-page/shoot.mjs $B --times=0,4000
```

- **Data.** `src/curation.json` holds the picks, the three callers and the area tiles. `src/neutral-names.json` holds the captions. `src/inventory.mjs` holds the deny lists and computes the facts.
- **Determinism.** Every SVG is deterministic. The JPEG tiles and the PNG are deterministic for a given Chromium build.
