# README.NFO Headers privacy policy

Effective date: 5 October 2026.

This policy describes **README.NFO Headers**, published by **Luke Woods**, and its data practices. It covers the plugin package and support route. ChatGPT, Codex and GitHub have their own privacy policies and account controls.

## Generation and publisher access

The plugin contains assistant instructions, reference files and local code helpers. It does not operate a publisher-hosted backend, usage analytics, advertising trackers, telemetry service or generation-data database. It does not automatically send your prompts, repository contents, generated images or saved draws to Luke Woods.

The assistant processes the project information you supply or authorise it to read in your ChatGPT/Codex environment. That host's account settings, permissions and privacy rules apply. When you ask it to read a public repository URL, its repository or browsing tools may contact GitHub or that repository's host. These are requests performed by your assistant environment; they are not a publisher-operated collection service.

## Local files and browser storage

Generated image batches can contain your project name, verified project facts, image files, source code, Markdown, the selected style IDs and a random-draw seed. These files are saved in the workspace or artifact storage used by your assistant. They remain there until removed through your file or host controls, subject to the host's retention practices. The publisher has no separate copy through this plugin.

The offline gallery can remember your favourite candidates using your browser's local storage. This stores a local gallery key containing the project name and draw seed, together with selected candidate IDs. It does not send that information to the publisher. You can clear it through your browser's site-data controls. The gallery works without this storage if the browser blocks it.

## Public support

Support uses public [README.NFO GitHub Issues](https://github.com/lukexyz/README.NFO/issues). If you post an issue, your GitHub identity and the text, files or screenshots you choose to include are visible to the publisher and other people who can view the public issue. The publisher may read and respond to those posts to help resolve the reported problem. Do not include secrets, sensitive personal information or private repository content.

Support posts are kept on GitHub while the issue content remains available there. The plugin does not copy them into a separate support database or set a separate retention period for GitHub's platform records. GitHub's own processing, retention and deletion practices apply, as described in its [privacy statement](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement).

## Sharing, retention and controls

There is no publisher-operated generation-data collection, sale or sharing pipeline. You decide whether to share generated files or publish a header in your repository. Doing so makes the information in those files accessible according to the destination's settings.

Use your assistant host's controls for prompts, uploaded files and hosted artifacts; local file controls for workspace outputs; browser controls for favourite selections; and GitHub controls for public issue content. Luke Woods cannot delete records controlled by ChatGPT/Codex or GitHub. For questions about this plugin policy or visible issue content, use the [support page](support.md) without posting sensitive information. Requests about a platform account's personal data should be directed to that platform.

## Changes

Changes to this policy will be published on this page with an updated effective date. Review the current policy before supplying project information.
